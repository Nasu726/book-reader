# AI Reader

A provider-independent, mobile-first web reader for PDF and EPUB documents with selection-focused AI actions, highlights, notes, vocabulary, and reading-position restoration.

## Requirements

- Node.js 24+
- npm

## Setup

1. Install dependencies:

   ```bash
   npm install
   ```

2. Create `.env.local` from the template and fill in the values:

   ```bash
   cp .env.example .env.local
   ```

3. Generate a single-user password hash without placing the plaintext password in configuration:

   ```bash
   node --import tsx -e 'import("./src/server/auth/password.ts").then(async ({ hashPassword }) => console.log(await hashPassword(process.argv[1])))' 'your-strong-password'
   ```

4. Initialize the SQLite database:

   ```bash
   npm run db:migrate
   ```

5. Start production locally:

   ```bash
   npm run build
   npm run start
   ```

Open `http://localhost:3000`, then sign in with `AUTH_USERNAME` and the password represented by `AUTH_PASSWORD_HASH`.

## Configuration

| Variable | Required | Purpose |
| --- | --- | --- |
| `DATABASE_PATH` | No | SQLite database file path. The app defaults to `book-reader.db`; migrations default to `data/book-reader.db`. Set one explicit absolute path for both. |
| `AUTH_USERNAME` | Yes | Single authorized username. |
| `AUTH_PASSWORD_HASH` | Yes | Scrypt hash generated by the setup command; never store plaintext passwords. |
| `AI_PROVIDER` | No | Set to `openrouter` (default) or `mock` for tests only. |
| `AI_MODEL` | Required for OpenRouter | Provider model identifier. |
| `OPENROUTER_API_KEY` | Required for OpenRouter | Server-side API credential. Keep this value out of client bundles and source control. |

## Verification

Run lint, typecheck, unit tests, Chromium E2E tests, and a production build:

```bash
npm run verify
```

For an isolated E2E database or additional browser projects:

```bash
DATABASE_PATH=/tmp/book-reader-e2e.db npm run test:e2e
E2E_PROJECTS=chromium,webkit npm run test:e2e
```

WebKit execution depends on host browser dependencies.

## Data and backup

The application stores documents, metadata, highlights, conversations, notes, vocabulary, progress, and sessions in one SQLite database configured by `DATABASE_PATH`. It enables WAL mode for concurrent local access.

Back up the complete live set while the server is stopped:

```bash
sqlite3 "$DATABASE_PATH" ".backup '/secure/backup/book-reader.backup.sqlite'"
```

When restoring, replace only the backed-up database file and remove any stale `-wal` or `-shm` files belonging to the previous database.
