# book-reader

A mobile-first web reader for PDF and EPUB documents with highlights, notes, vocabulary, and reading-position restoration. Questions and translation are left to the tools that already do them well (Claude, ChatGPT, DeepL); the reader makes the passage easy to take there. See `docs/DECISIONS.md` D-52 for the turn away from built-in AI, and `docs/WORKMAP.md` for where the rewrite towards an Obsidian vault as the store stands.

## Requirements

- Node.js 24+
- npm

## Setup

1. Install dependencies:

   ```bash
   npm install
   ```

2. Create `.env.local` from the template and fill in the values:

   ```bash
   cp .env.example .env.local
   ```

3. Generate a single-user password hash without placing the plaintext password in configuration:

   ```bash
   node --import tsx -e 'import("./src/server/auth/password.ts").then(async ({ hashPassword }) => console.log(await hashPassword(process.argv[1])))' 'your-strong-password'
   ```

4. Initialize the SQLite database:

   ```bash
   npm run db:migrate
   ```

5. Start production locally:

   ```bash
   npm run build
   npm run start
   ```

Open `http://localhost:3000`, then sign in with `AUTH_USERNAME` and the password represented by `AUTH_PASSWORD_HASH`.

## Configuration

| Variable | Required | Purpose |
| --- | --- | --- |
| `DATABASE_PATH` | No | SQLite database file path. Defaults to `./data/book-reader.db` for both the application and `npm run db:migrate`. |
| `AUTH_USERNAME` | Yes | Single authorized username. |
| `AUTH_PASSWORD_HASH` | Yes | Scrypt hash generated by the setup command; never store plaintext passwords. |
| `DOCUMENT_STORAGE_DIR` | No | Directory holding imported PDF and EPUB bytes. Defaults to `./data/documents`. Back this up together with the database. |

## Verification

Run lint, typecheck, unit tests, Chromium E2E tests, and a production build:

```bash
npm run verify
```

`npm run test:e2e` starts its own development server and gives each run a fresh
database and document directory under the system temp path, so it never touches
the configured `DATABASE_PATH`. Stop any development server on port 3100 first;
the suite deliberately refuses to reuse one it did not configure.

## Data and backup

The application stores metadata, highlights, notes, vocabulary, progress, and sessions in one SQLite database configured by `DATABASE_PATH`, with WAL mode enabled for concurrent local access.

Imported document bytes are **not** in the database. They live in `DOCUMENT_STORAGE_DIR` behind the `DocumentStorage` boundary, and the database keeps only an opaque reference. A complete backup therefore needs both. Documents imported before this split are still readable directly from the database.

Create an online snapshot with SQLite's backup API. Stop the server first if you need a point-in-time copy without writes in progress:

```bash
npm run db:backup -- /secure/backup/book-reader.backup.sqlite
```

Stop the app before restoring. The command validates backup integrity and table presence, then replaces the database and removes stale WAL/SHM files:

```bash
npm run db:restore -- /secure/backup/book-reader.backup.sqlite --replace
npm run db:migrate
```

## Deployment

Use a Node.js host with a persistent volume. The application requires server routes, authenticated uploads, SQLite, and server-side provider access, so static hosting targets are not compatible.

A production container can be built and run with:

```bash
docker build -t book-reader .
docker run --rm -p 3000:3000 -v book-reader-data:/data book-reader
```

Mount `/data` on the host's persistent storage in production; it holds both the database and the imported documents. Set `AUTH_USERNAME` and `AUTH_PASSWORD_HASH` as secret environment variables. Startup automatically runs migrations against `/data/book-reader.db`.
